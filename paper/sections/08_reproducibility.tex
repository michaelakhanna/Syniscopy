\section{Fluorescence and Electron-Microscopy Fidelity Paths}
\label{sec:appendix-non-scalar-modalities}

\paragraph{Transmission electron microscopy phase contrast.} The transmission-electron-microscopy path supports configurable backend fidelity through \texttt{tem\_backend}: physical split-step multislice (\texttt{multislice\_physical}), weak-phase CTF proxy (\texttt{ctf\_proxy}), reduced-slice proxy (\texttt{multislice\_lite}), or the older Syniscopy split-step path (\texttt{syniscopy\_multislice}). It exposes accelerating voltage, Cs, defocus, partial coherence, slice count/thickness, projected-potential scale, dose, and objective-aperture controls. The comparison profiles use \texttt{multislice\_physical}; CTF and reduced-slice modes are retained as lightweight diagnostics, and rows remain reference-unvalidated unless an external multislice reference hash is supplied.

\paragraph{Scanning electron microscopy secondary-electron contrast.} The scanning-electron-microscopy path now preserves material-resolved source channels before transport. The comparison branch uses \texttt{sem\_model=\allowbreak physical\_electron\_transport} and \texttt{sem\_backend=\allowbreak monte\_carlo\_physical}, then builds one material-specific electron-transport kernel per source channel. The current baseline uses screened-Rutherford elastic scattering, Joy--Luo continuous stopping, Kanaya--Okayama range diagnostics, and an empirical 20~keV backscatter-coefficient check. \texttt{sem\_physical\_elastic\_model=\allowbreak mott\_browning} enables the Browning empirical Mott surrogate for sensitivity studies; it is not the default because it currently worsens those anchor residuals in this simplified transport geometry. Alternate branches are \texttt{monte\_carlo\_transport}, \texttt{syniscopy\_transport\_lite}, \texttt{gaussian\_probe\_proxy}, \texttt{interaction\_volume\_proxy}, and \texttt{reference\_kernel\_table} interpolation paths. Interaction-volume coupling, topography coupling, detector acceptance, escape-depth, and charge-response behavior are configurable terms in the transport-calibrated paths, with simpler proxy terms retained when a compact option is selected.

\paragraph{Widefield and total internal reflection fluorescence.} The fluorescence paths integrate \path{MaterialProperties.fluorophore_density} over the particle footprint, modulate by excitation/emission spectral factors derived from \path{fluorescence\_excitation\_wavelength\_nm} and \path{fluorescence\_emission\_wavelength\_nm}, convolve with the selected emission point-spread-function backend, and add sample-environment autofluorescence/excitation modulation. The fluorescence response is determined by the material and particle configuration supplied to the simulator. The default fluorescence paths use projected source maps with the parametric emission PSF; TIRF additionally applies the evanescent chord-integrated source weighting. The \texttt{vectorial\_photophysics} branch remains available for z-sliced vectorial-emission calculations with frame-wise bright-to-dark and dark-to-bright Markov transition rates, bleaching, and detector-quantum-efficiency scaling.

A cropped experimental recording with pixel pitch $p$ and crop size $L\times L$ maps to a simulator pixel size of $p$ and an image size of $L$ pixels; if the experimental recording was binned $2\times2$, use twice the native camera pitch. Syniscopy writes lossless contrast-analysis PNG frame sequences for segmentation/training workflows and separately records raw-camera signal products for audit: a windowed raw-signal preview video by default, plus optional raw-camera frame sequences and raw signal/reference arrays when requested. Pattern fitting from experimental recordings is available for the implemented gold-hole pattern family, allowing pitch and radius estimates to seed a bench-matched sample-environment configuration while unresolved jitter and shape-regularity fields remain explicit metadata. A one-to-one pixel match to a real bench remains approximate because stray light, dust, gain nonlinearity, out-of-focus particles, and alignment errors are not fully absorbed by the current parameter set; source-matching residual structure is exposed through explicit sample-environment roughness/speckle fields \texttt{sample\_environment\_pattern\_roughness\_*} (static, flicker, or source-matched modes) with source coupling options \texttt{independent}, \texttt{coherent\_amplitude}, \texttt{field\_weighted}, \texttt{scene\_weighted}, and \texttt{channel\_weighted} (default: \texttt{channel\_weighted}).

The detected-quanta-normalized analyses use an analysis-level common budget $N_Q$ recorded in experiment output together with Contract-Q normalization metadata and lateral spectral sampling/support fields. That analysis budget is distinct from the default public configuration dictionary, where cross-microscope comparisons use each microscope's own count/dose scale parameters unless explicitly configured for a post-hoc normalization sweep.

\section{Reproducibility Workflow}
\label{sec:reproducibility}

The supplemental notebooks generate the raw experiment outputs used by the manuscript when executed in order. The paper-facing tables and figures are assembled from those outputs by the paper artifact-generation workflow, which writes \path{paper/figures/artifact-provenance-manifest.json}. Rerunning E03 writes \path{supplemental/outputs/E03/comparison_contracts_manifest.json} and \path{supplemental/outputs/E03/artifact_dependency_graph.json}, so paper artifacts can be traced back to comparison contracts, source-output files, generator paths, and SHA-256 hashes. The results reported here were produced with the current checked-out Syniscopy notebook bundle in this repository. The deterministic simulator analyses use fixed seeds and run on a CPU runtime. Larger arrays and videos can be regenerated from the paper-facing notebooks.

\paragraph{Microscope-set configuration input.}
The comparison notebooks consume a microscope-set configuration: a JSON document listing named microscopes, each declaring its contrast modality and a partial overlay of only the instrument parameters that microscope sets, layered onto the shared scene and shared defaults. A microscope's overlay therefore carries solely the parameters its modality consumes, so an electron microscope is never asked for a pupil-sampling value and an optical microscope is never asked for an accelerating voltage. The fixed-instrument modality comparison used for the configured-profile tables is generated from this same input by emitting one microscope per modality from a single shared instrument overlay; no separate code path is required. Because the comparison unit is a microscope, the ranking export is microscope-keyed --- a \path{microscope_ranking.csv} in which each row names a microscope and records its contrast modality in a dedicated column --- and the fusion, time-allocation, registration, and detected-quanta exports key their rows on microscope names rather than on bare modality strings. The notebooks do not require a new numbered experiment: E03 generalizes from a modality list to a microscope set (with the fixed-instrument modality sweep as its default input), E01 renders its forward panel from the same microscope set, and E04 already carries per-instrument configuration for its native-regime rows. An optional cross-microscope demonstration --- the same modality configured on two different instruments, and different modalities on different instruments --- can be added as a small additional notebook (E06) once the engine is microscope-keyed, but it reuses the E03 machinery and is not load-bearing for the contracts below.

Core comparison claims are contract-specific and map to explicit output files in \path{supplemental/outputs/} when the corresponding notebook pipeline is run:
\begin{itemize}
\item Contract-LP (lateral Cram\'{e}r--Rao ranking): when generated, \path{supplemental/outputs/E03/microscope_ranking.csv} (microscope-keyed, with a modality column) together with the lateral derivative-basis, Nyquist-band, and boundary-support fields emitted with the same rows.
\item Contract-LZ (\(\mathrm{SE}(3)\) and axial diagnostics): when generated, \path{supplemental/outputs/E03/cross_modality_axial.csv} and \path{supplemental/outputs/E03/axial_convergence_crlb.csv}; per-composite orientation support is in \path{supplemental/outputs/E02/orientation_crlb.csv} and assembled into \path{figures/orientation-crlb-table.tex}.
\item Contract-Q (detected-quanta normalized comparison): when generated, \path{supplemental/outputs/E03/detected_quanta_normalized.csv} and \path{supplemental/outputs/E03/detected_quanta_normalization_metadata.csv}, plus budget sweep artifacts in \path{figures/detected-quanta-budget-pareto.png}.
\item Contract-NR (native-regime source-use context): when generated, \path{figures/native-regime-localization-comparison-table.tex}, produced from the E04 source-use audit rows.
\end{itemize}
The deterministic simulator-side checks and notebook diagnostics in Sections~\ref{sec:results} and \ref{sec:appendix-non-scalar-modalities} are intended for conceptual and software validation; they are not substitutes for physical-instrument calibration. Checks that rely on analytic limits cite the underlying physical equation or reference model instead of being promoted to empirical instrument validation. External-reference comparisons use independent packages only where that strengthens a claim, such as Mie amplitudes against \texttt{miepython} and classical Mie theory \cite{mie-scattering,miepython-software}, coherent thin-film amplitudes against the \texttt{tmm} transfer-matrix implementation \cite{tmm-byrnes}, and TEM multislice fixtures generated with abTEM and ASE when such a fixture is explicitly supplied \cite{abtem-code,ase}. A backend is therefore treated as reference-validated only when the selected external fixture or published-reference tolerance sweep has passed and the corresponding metadata hash/status is recorded.

The dataset-generation routine seeds each corpus from the caller-provided seed plus the video index. The dataset metadata records per-video parameter dictionaries, the supervision policy, and the annotation schema, enabling regeneration of individual videos.

\section{Downstream Segmentation Interface}
\label{sec:downstream-segmentation-interface}

Syniscopy datasets can be consumed by downstream segmentation models through lossless contrast-analysis PNG frame sequences, target masks, ignore masks, and optional loss-weight maps. The raw-signal AVI is a camera-style audit preview, not the default training target. Optional raw-camera frame sequences and raw signal/reference arrays serve as diagnostic records. The repository keeps generic starter notebooks for Segment Anything Model 2 workflows, but those starters are user utilities rather than paper-facing experiments and are not used as evidence in this manuscript.


\paragraph{Source-use separation.}
Native-regime source use is split into two generated tables. The localization-comparison table contains computed Syniscopy CRLB rows only when the cited source reports a localization scale. The source-provenance table contains citation and parameter-use cards only; those rows do not carry computed CRLB values and are not validation rows.

\paragraph{Convergence and artifact status.}
The paper-facing E03 tables are gated by generated sampling/convergence/status fields.
